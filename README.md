**Версия:** 1.5  
**Автор:** Vladislav Nikonenko (идея и разработка)  
**Лицензия:** Проприетарная — см. [LICENSE](./LICENSE)

---

## Описание

СК-пилот — веб-приложение для инженеров строительного контроля. Позволяет вести
ежедневные сводки по объектам: персонал, входной/операционный/приёмочный контроль,
замечания, предписания, фотофиксация, ИД/КС. Администратор видит сводки всех
инженеров в одном интерфейсе.

Компаньон системы **TeamJect** (`app.teamject.com`) — предписания и акты.

---

## Стек

- **Backend:** Python, Flask, gunicorn
- **База данных:** SQLite (WAL-режим)
- **Frontend:** Vanilla JS, три SPA-страницы (без фреймворков)
- **Деплой:** nginx (reverse proxy) + gunicorn

---

## Локальный запуск

```bash
pip3 install flask flask-cors
python3 app.py
```

Приложение доступно на `http://localhost:5000`.

## Выбор базы данных

Приложение работает и на SQLite, и на PostgreSQL. Выбор — переменной
окружения, без правки кода:

```bash
python3 app.py                      # SQLite (по умолчанию)
SK_DB_TYPE=postgres python3 app.py  # PostgreSQL
```

Переменные подключения к PostgreSQL: `SK_PG_HOST`, `SK_PG_PORT`, `SK_PG_DB`,
`SK_PG_USER`, `SK_PG_PASSWORD` — либо одна строка `SK_PG_DSN`.

Схема PostgreSQL создаётся один раз из `db/schema_postgres.sql` — это
единственный источник правды по структуре базы. `auto_migrate()` под
PostgreSQL не выполняется: он относился к истории конкретного файла
`pilot.db`.

Перенос данных из SQLite в PostgreSQL с сохранением всех идентификаторов:

```bash
python3 scripts/migrate_to_postgres.py --sqlite /var/sk-pilot/db/pilot.db --pg "host=localhost dbname=sk_pilot user=sk password=..."
```

## Автотесты

Набор проверок «система жива и ведёт себя как раньше»: аутентификация, права
по ролям, рабочий цикл инженера, синхронизация подрядчиков, управление
пользователями, экспорты.

Установка зависимостей (один раз):

```bash
pip3 install -r requirements-dev.txt
```

Запуск из корня репозитория:

```bash
pytest
```

Полезные варианты:

```bash
pytest -v                          # с именами тестов
pytest tests/test_auth.py          # один файл
pytest -k "пароль"                 # по подстроке в имени
```

Тот же набор прогоняется на PostgreSQL — так проверяется, что после
переезда поведение не изменилось:

```bash
SK_DB_TYPE=postgres SK_PG_DB=sk_test pytest
```

Имя базы обязано содержать `test`, иначе прогон прерывается: это защита
от запуска тестов на боевой базе.

**Тесты не имеют доступа к боевой базе.** Перед импортом приложения
`tests/conftest.py` выставляет `SK_DB_PATH` и `SK_UPLOAD_DIR` на временную
папку, создаёт базу с нуля и удаляет её после прогона. Если путь к базе
почему-то окажется вне временной папки, прогон прерывается с ошибкой,
не выполнив ни одного теста.

Перед каждым тестом база восстанавливается из эталонного снимка, поэтому
тесты не влияют друг на друга и порядок запуска не важен.

## Структура файлов

```
pilot/
├── app.py          — бэкенд (Flask)
├── db/
│   ├── schema.py   — схема SQLite, get_db(), auto_migrate()
│   └── pilot.db    — база данных (создаётся автоматически)
├── static/
│   ├── login.html  — страница входа
│   ├── report.html — форма сводки инженера
│   └── admin.html  — панель администратора
├── uploads/        — загруженные фото и протоколы
├── tests/          — автотесты (pytest), работают на временной базе
│   ├── conftest.py         — изоляция от боевой базы, фикстуры, тестовые данные
│   ├── test_auth.py        — вход, выход, смена пароля
│   ├── test_permissions.py — права по ролям
│   ├── test_engineer_flow.py — рабочий цикл инженера
│   ├── test_contractors.py — синхронизация подрядчиков
│   ├── test_users.py       — управление учётными записями
│   └── test_exports.py     — экспорты и резервная копия
├── pytest.ini      — настройки запуска тестов
├── LICENSE         — проприетарная лицензия
└── README.md       — этот файл
```
